# Les Octonautes sauvent la planète avec Qwik, un framework JS qui peut beaucoup pour alléger vos applis web

**Christophe Frezier · Vendredi 10 novembre · Salle 3 (H1+H2)**

## Pourquoi regarder le JavaScript livré

Christophe Frezier présente Qwik en prenant les Octonautes comme fil conducteur. Il revient sur les sites statiques, la génération côté serveur puis les applications qui exécutent davantage de code dans le navigateur. Le problème est le travail nécessaire avant que la page réponde : transférer, lire et exécuter du JavaScript peut demander beaucoup de temps sur une connexion lente ou un appareil modeste.

## Charger le comportement quand il devient utile

Le talk présente la découpe du JavaScript et la résumabilité. L’idée est de transmettre assez d’état pour reprendre l’application sans refaire systématiquement tout le travail de démarrage dans le navigateur. Les parties de code peuvent ensuite être chargées au moment où une interaction les demande. Cette séparation impose des contraintes : une fonction extraite doit pouvoir retrouver les valeurs dont elle dépend. Christophe évoque notamment les limites autour des closures et des données que l’on peut transporter.

## Relier l’interface au serveur

Les exemples abordent aussi les routes et les points d’accès côté serveur. Un fichier associé à une route peut fournir une réponse, dont du JSON et un statut. La démo montre ainsi comment une application peut associer les pages, leurs données et les opérations nécessaires aux interactions. Le choix du framework couvre plusieurs étapes du parcours de la requête jusqu’à l’action de l’utilisateur.

## Ce que j’en garde

Pour comparer les approches, mesurer le JavaScript effectivement transféré et exécuté avant la première interaction, puis observer les requêtes provoquées par les interactions suivantes. La découpe doit améliorer l’expérience sur le parcours qui compte pour le produit.
